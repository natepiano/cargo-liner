### Added
- First version, at `0.1.0-dev`: a terminal UI on `tui_pane`, reached as `cargo-handler` or `cargo handler`.
- A tile grid opening on the summary cell. `+` opens a cell, `-` closes an empty one, the arrows and Tab move the focus ring, and a click focuses the cell under it.
- The summary cell lists the top-level Claude Code and Codex agents on this machine and on each remote machine: pid, agent, name, status, age and directory, oldest first under a heading and a column-label row per machine. An agent started by another agent is left out, and so is a session another agent opened in tmux, found by the `tmux new-session` call in that agent's transcript; so is a `codex app-server`, except the one the ChatGPT desktop app runs on macOS, listed as `ChatGPT`.
- Agent cells: every agent someone can talk to gets a cell titled with its name, each top-level agent followed by the sessions it opened in tmux. The cell's header gives the agent's pid, program, status, age, machine and directory, and for a launched session the agent that opened it; below it a table lists what the agent is running, indented by level: its shell tool's commands, named by the Bash call's description; the Claude Code and Codex processes those start; a Codex app server's threads; its subagents; and the sessions it opened. The probe's JSON carries each row's `launched_by` and `children`, at schema version 2.
- A Codex row is named for the thread its `codex` started, matched in `~/.codex/state_<n>.sqlite` by directory and start time: the thread's name, else its first prompt, else the command line after `codex` or `pid <n>`.
- A `desktop` column before `directory` in the summary, and `· <desktop>` after the machine in each agent cell's header: the KDE virtual desktop the agent's terminal window is on, read at most every 5 seconds from one `KWin` script listing every window's pid, caption and desktops. The window is the one the agent's nearest terminal ancestor owns, narrowed by caption when that terminal owns several (Claude Code's session name behind its status glyph, or Codex's `<thread> | <directory>`); an agent tmux holds is found through its pane's session and the clients showing it. A window on every desktop says `all desktops`, and an agent with no matched window -- detached, remote without KDE, or off Linux -- shows `—`. The probe's rows carry `desktop`, still at schema version 2.
- `[machines] remote` in `config.toml`, edited under Machines in the settings overlay: ssh host names probed every 5 seconds with `ssh <host> cargo-handler probe`, over a shared control socket. A remote that fails keeps its heading with the reason: `unreachable`, `cargo-handler not installed`, a probe version mismatch, `timed out`, or the probe's exit status.
- A hidden `probe` subcommand that prints this machine's agents as one line of JSON.
- Theme roles `claude`, `codex`, `busy`, `shell`, `idle` and `unreachable` under `[variants.roles]`, set in all four built-in themes.
- Rainbow names: each agent cell takes the next color of a rainbow in cell order -- red, orange, yellow, green, cyan, blue, violet, then red again -- and draws its title in it, and the summary draws that agent's name in the same color, so a row and its cell pair up at a glance. A launched session takes a color of its own though the summary leaves it out. Inside a cell, the agent named after `launched by` and each session the agent opened are drawn in the colors of their own cells. The colors are theme roles `rainbow_red`, `rainbow_orange`, `rainbow_yellow`, `rainbow_green`, `rainbow_cyan`, `rainbow_blue` and `rainbow_violet`, set in all four built-in themes.
- Agent cells are laid out for their width, spending rows where a narrow cell would otherwise cut its header, its directory or a name short. Where the header's one line would be cut, it stands as a block, one fact to a line after a label column: `agent` with the pid, `status` with the age, `machine`, `desktop`. A directory too long for its line breaks after a `/`. Where the table would cut a name, each row stands as an entry of its own -- `<kind> · <age> · pid <pid>`, the kind indented by level -- with its name in full below it, broken before a space or after a `/` when it is still too long. A cell asks the grid for the rows it takes at its own width.
- `[tiles] fill` decides how the grid's cells spread over its columns, stepped under Tiles in the settings overlay. `redistribute`, the default, keeps every column within one cell of the others, the taller ones first: twelve cells stand as three columns of four, thirteen as four, three, three and three, fourteen as four, four, three and three. `add_new` fills a column at a time, so the cell that opens a new column stands in it alone. The number of columns is the same either way.
- `[tiles] widen_summary`, on by default and stepped under Tiles in the settings overlay: the summary widens over the next columns until its widest line -- a machine's heading, or an agent's row with its directory written out in full -- fits or it reaches the right edge, keeping the height its own column gives it. The cells of a column it covers divide what is left below it, and a column whose cells would no longer fit there stops it. Off, the summary stays in its own column and cuts a long directory short.
- The attract screen from `tui_pane`: it comes on over the idle grid after a quiet spell, and on `a`. `r` draws one at random and `u` undoes that replacement.
- Attract favorites: `ctrl-s` saves the parameters on screen, `ctrl-o` opens the saved list, `m` shows one at random. They are kept in `favorites.toml`.
- The framework overlays: `s` settings (appearance, initial rows, remote machines, file paths, notices), ctrl-k keymap editor, `?` shortcuts.
- `config.toml`, `keymap.toml` and `themes/` under `<os config dir>/cargo-handler/`, with four built-in themes mirrored as TOML under `themes/`.
- On KDE Plasma the attract screen draws the windows behind the terminal once `assets/cargo-handler.desktop.in` is installed: `scripts/install-desktop-entry.sh --crate cargo-handler`, or the script given a binary named `cargo-handler`. `KWin` grants window capture by executable path, so without the entry the backdrop is the wallpaper.
